# 收尾窗口

用于逃离「整合目标分支 → 验证 → 目标分支前进 → 再整合」循环。窗口是协作约定，不替代仓库调度器、资源准入或合并门禁。

## 进入条件

已有收尾授权、PR 尚未合并且实现与审查已收敛，再满足任一项就申请：

- 同一仓库最新创建的 PR 编号减本 PR 编号 **大于 20**，并已因目标分支前进被迫重整合至少一次。
- 不论编号差，已连续两次因目标分支前进而被合并入口拒绝，需要整合并重验证。

最新 PR 包括已关闭/合并项，按创建时间取最新；同仓库比较，记录查询时间、两个编号与实际拒绝原因。编号差只是老 PR 预警，不代表提交落后数；取不到编号仍可按实际循环触发。普通测试失败、审查未收敛先修问题。

## 排队与独占

在要协调的环境本机执行（Node 需支持 `node:sqlite`）：

```text
node <t3-code技能目录>/scripts/finish-window.mjs request <本线程id>
node <t3-code技能目录>/scripts/finish-window.mjs status <本线程id>
node <t3-code技能目录>/scripts/finish-window.mjs release <本线程id>
```

状态放在本机 `~/.config/bstack/state/finish-window.sqlite`，与可同步的偏好配置分开；该 state 目录已由 bstack 配置同步排除。所有仓库共用一条队列，先来后到按首次成功登记的 ticket 排序。SQLite 事务保证同一时刻只有一个 owner；同线程重复申请保留票号，持有者重复申请不会续租。所有 harness 应使用同一 OS 用户与该文件；文件不共享的用户/容器不在此保证内。

只有返回 `granted:true` 且当前时间早于 owner.expires 才能协调。等待者记录前方线程和票号，继续轻任务；等持有者释放消息再 request。消息遗漏时可在下一次正常唤醒时 request，排队条目一小时未刷新自动撤销。窗口自获批起固定一小时，到期重新排队。工具不可用或事务失败时保留正常调度，不靠广播自封协调者。

完成标准：持有者记下 ticket、expires、PR URL、目标分支、当前 HEAD 和要完成的检查；等待者没有发送让路广播。

## 协调与让路

持有者用 `t3_thread_list` 列出本环境各项目未终结线程，结合最近 run 与 `t3_thread_read` 判断活跃者；读取消息中提到的线程前先读该线程。通过 `t3_thread_send` 向活跃的顶层线程发一次协作消息（子任务由其负责人转达）。消息包含：

> 收尾窗口：owner=<线程链接>，ticket=<票号>，截止=<UTC时间>；PR=<URL>，目标=<仓库/分支>，HEAD=<SHA>，剩余=<检查/合并>。请在安全边界暂缓本机新重任务；同仓库同目标分支暂缓合并与自动合并。请回复正在运行的任务、安全边界和预计释放时间。释放或到期后恢复正常调度。

收到消息的线程先用 status 核实 owner、ticket 与截止时间，然后执行让路：

- 本环境所有项目：正在运行的重任务自然完成，在安全边界暂停后续重任务和消耗同类资源的新委派；继续编辑、查询、文档检查和低资源测试。按实际 CPU、内存、I/O 与设备占用判断轻重，不因命令名含「全量」「检查」就停工；不确定时先看脚本入口与已有耗时证据。回复无法立即让出的资源与预计时间。
- 同仓库同目标分支：暂缓合并及直接推送目标分支；已有自动合并计划由所属线程安全暂停。其他仓库的提交、推送与合并可继续。仅租约存在但尚未核实持有者的仓库/目标分支时，继续轻任务并补核冲突范围，不将全机视为冻结。
- 新唤醒或新开工线程在启动重任务、合并前查 status，遵守有效窗口。到期或 owner 消失即可恢复；延迟到达的旧 ticket 消息忽略。

持有者记录回执、未回复与不能让路项；未回复不算资源已腾空，继续遵守调度器和真实资源门禁。协调只请求其他线程在自己的安全边界让路；进程、锁和工作区仍由原线程负责。用户明确要求的更高优先级工作由所属线程回复冲突，持有者据此缩小窗口或释放。

完成标准：回执和剩余占用可核对，重任务真正通过资源准入才开始。本环境窗口无法冻结其他环境或人的提交，因此不承诺目标分支绝对静止。

## 收尾与释放

持有者冻结本次待合并 HEAD，按仓库入口完成剩余验证与合并。目标分支前进时先尝试允许的合并入口；确实要求整合才更新。复用证据前核对源码、依赖、工具链与覆盖，变化部分补跑；必需检查仍按仓库策略在待合并 HEAD 上满足。

PR 合并、用户取消、出现需重新实现/审查的 blocker，或只能等外部审批/长期 CI 时立即 release，把资源还给队列。只要租约仍有效，短暂验证等待可保留窗口。每次发协调消息、启动下一项重任务或合并前重查 status；到期后停止使用协调优先权，已运行任务按安全边界结束。再次申请排到队尾，不连续续占。

释放后给原收件人发送 ticket 对应的释放消息，并通知 queue 首位重新 request；释放本身不自动授予不在线的等待者。异常退出由固定到期兜底，其他线程凭状态恢复，无需删除数据库或结束他人进程。

完成标准：状态里本线程已非 owner、自己的排队项已撤销；已通知受影响线程，汇报窗口结果及未解决的外部阻力。
