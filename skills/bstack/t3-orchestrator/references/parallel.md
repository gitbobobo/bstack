# 同一工作树并行写

多个写文件的子代理可同时跑在一个工作树，须全部满足，否则串行：

- 各自「可以改」的范围互不重叠；
- 都不碰共享文件（生成物、锁文件、全局配置、预算和基线清单）；
- 都不提交，也不跑改写整个仓库的命令（生成器、全仓库格式化、依赖安装）；
- 后一个任务不需要参照前一个的产出（例如 OHOS 要照着 desktop 的新代码对齐语义，只能串行）。

派发时：

- 每个子代理的「范围」写明同一工作树还有哪些任务在改哪些目录，要求不碰、不回滚 `git status` 里的这些改动。
- 「验收标准」只写本范围的定向检查（单个 crate 的 `cargo check`/`cargo test`、单个包的 lint）。并行 cargo 争用同一个 target 目录，`Blocking waiting for file lock` 是正常等待。
- 共享文件和生成器由你在所有写任务验收后统一处理。只读调研和审查随时可并行。
