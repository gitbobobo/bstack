# 重验证、截图与辅助工作树

- **资源**：跑或派全量构建、门禁、E2E、截图、生成器之前，按 [资源不足时](resources.md) 查本机磁盘与内存。重命令走机器的调度入口与资源限额，限额取设备配置。
- **审查者**默认只读源码及已有证据；需要额外的重检查时提出请求，由最终验证负责人安排。
- **端到端验证或截图任务**：把项目 AGENTS.md 的相关约束原文写进「约束」，注明场景首次开始时间、已消耗时间、重复崩溃计数和现有统一入口；时限与停止条件跨代理重试累计，以项目规则为准。截图前预检已有产物、harness 入口与上传条件，优先复用现有设施；环境事实只写查证过的；只释放本任务拥有的设备和进程。「回报」加上首次开始时间、累计耗时、崩溃计数与替代证据；续跑时把这三项原样带进「背景」，不重置。
- **辅助工作树**（基线截图、对照、复现）：建在 `<T3 工作树根>/<仓库目录名>/tmp-<用途>-<短 id>`（缺省 `~/.t3/worktrees/…`），路径记进账本，用完当轮 `git worktree remove --force`；派给子代理时把删除写进它的「验收标准」。漏删的由 `t3-worktree-gc.mjs` 兜底，但构建产物会先占着磁盘。
- **接力定时任务**（等检查结果、等合并条件）每次醒来只查状态。要重跑重验证，提示词里写明触发重跑的变化（新提交、新假设、环境变化）；条件没变就只汇报状态后结束本轮。
