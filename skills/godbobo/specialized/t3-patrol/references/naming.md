# 线程命名格式

命名体检命中（`needsRename` 为 true）或交接新建线程时读这一篇。

标题是侧栏里的唯一识别入口。用 `t3_thread_update`（`action:"rename"`、`title`、`threadId`，带该环境的 `environmentId`）改成 SKILL.md 第 2 节那句「具体在做什么」的压缩版，格式 `<标识> <主题>[-<段>]`，宽度 ≤ 20 个汉字（ASCII 算半个，侧栏才不会截断）：

- **标识**：有 open PR 用 `#<PR 号>`，无 PR 但有 issue 用 `INT-<号>`，都没有用类别词——按内容归类选一个（审查、巡检、调研、实施、运维、排查都行），不是固定清单。
- **主题**：3–10 字说清这件事，去掉 `feat(...)`/`fix(...)`、仓库名与「实施/处理」这类不载信息的词。主题永远取自第 2 节那句：快照的 `needsRenameThreads` 已带 `task`/`tail`/`prs`，「拿不到主题」不是跳过命名的理由；这些字段不够再读那条线程。`task` 只是派活模板、末尾附了 Fast Ship 问题 ID 时，主题取那条 issue 的标题（`GET /api/issues/{id}`）。确实没有 PR/issue/可抽取主题时，用 `<类别词> <首条消息关键词>` 兜底（类别词按内容选「运维/调研/巡检/实施」等，关键词取首条消息里最具体的对象），不写「待命名」「新线程」这类占位标题；之后拿到 PR/issue 再覆盖。
- **段**：同一需求拆到多端时加 `-Android`、`-Windows`、`-Swift`，否则同 issue 的几个线程在侧栏长得一模一样。

例：`#685 歌词-Android`、`#683 INT-1378 验收`、`INT-1550 灌队取消守卫`、`审查 #653 R4`。

标题只放稳定的信息：状态、轮次、模型名每轮都变，写进去会让标题抖动，每次改名还会刷新 `updatedAt`。

`renameReasons` 对应要修的地方：`raw` 是提示词原文堆砌（含 `/t3-orchestrator`、`Act as`、`## ` 或换行），整句重写；`wide` 压缩主题；`stale-id` 把标识换成 open PR 的号。
