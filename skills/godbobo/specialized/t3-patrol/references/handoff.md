# 收尾之后：交接与 settle

判定表命中「PR 已合并、`$pr-finish` 已跑完」时读这一篇。其余轮次用不到。

## 有无交接

收尾汇报里可能带一段交接提示词（`$pr-finish` 第 6 步），交给下一段工作，例如跨端对齐的下一个平台。

汇报里只要列了「交接项 / 后续工作 / 下一步交给谁」这类条目，就按有后续段处理——写进 issue summary 只是登记了事项，不替代提示词，是不是后续段由来源线程自己答，不由巡检定性。没给提示词就先发 `M13`（见 [messages.md](messages.md)），下一轮再交接。来源线程回复只是遗留登记、不需要新线程，才算没有交接。

## 有提示词时按顺序处理

1. **定目标环境**：交接里写了设备名就直接用；只写技术栈（如「Android + Rust」）时，查来源仓库文档里的设备分工，换算成设备；交接没指定设备，仓库也没有设备分工，就留在来源线程所在的环境。设备按 SKILL.md「0. 前提」的环境对照表找到环境。

   设备在对照表里找不到、目标环境不可达、目标环境里没有这个仓库的项目，或者交接写的是「以后再安排」：都不交接，列进「需要你决定」，来源线程先不 settle。

2. **查重**：在目标环境用 `t3_thread_search` 搜 PR 号和来源线程 id，已有线程接过这段工作就跳过新建。

3. **看容量**：远程环境拿不到负载和磁盘信息，以占用名额的线程数为准（快照里的 `activeTopLevel`，`occupying` 列出是哪些）。占用名额的是：有活跃 run 的顶层线程（含「代码审查 · PR #N」线程，不含子代理线程），以及 PR 仍 open、最近一次 run 在 2 小时内结束的线程——等审查的线程在两轮之间会暂时 completed，但工作树和编译资源还占着。PR 已合并或关闭（工作树已回收）、没有 PR 又没在跑的线程不占名额，所以来源线程本身通常不算。

   已达 5 个就本轮不建。目标是本机时另外跑 `df -h ~` 看剩余空间，不足 20 GB 也不建。满了就把这次交接记成「等待空位」：来源线程先不 settle，下一轮重新检查；同一环境有多个交接在等时，按来源线程收尾的先后顺序建，建到上限为止。

4. **新建线程**（前提：第 3 步写出了目标环境的 `activeTopLevel`，且小于 5）：

   - `t3_thread_launch` 带上目标环境的 `environmentId`；
   - `projectId` 取目标环境里同一仓库的项目（`t3_thread_list` 找同仓库的近期线程，用它的 `projectId`）；
   - `modelSelection` 取 `{instanceId:"pi", model:<SKILL.md「模型优先级」里当前可用档位>, options:{thinking:"medium"}}`；
   - `workspaceStrategy` 取 `{type:"worktree", baseRef:<仓库默认分支>, startFromOrigin:true}`；
   - 标题按 SKILL.md 的命名格式（`#PR 号 / INT-号 + 主题 + 端`），用该项目以往标题的语言和写法；
   - `message` 原样贴交接提示词，开头如有斜杠命令就保持在第一行，末尾另起一行写 `> 交接自 <来源线程 link>`。

   交接写的是多段接力（如「先发 A 设备，合并后换新 PR 号再发 B 设备」），本轮只建第一段，并在 message 末尾再加一行 `> 后续：合并后按同一提示词换新 PR 号交接给 <下一台设备>`，让新线程收尾时给出下一段的交接。

5. **settle 前确认没有后续段**，再 settle：两处都要看过——收尾汇报，和**原任务首条消息 / 关联 issue**。「跨端」「其他端」「后续平台」「再发 Windows 段」这类分工常常只写在任务书里，收尾汇报不一定重复；只看汇报就 settle，会把「这条还差一段」一起关掉，空窗期没人接手（INT-1280 周三段只做了 Mac mini 段，settle 后断了 14.9 小时）。

   任务书里有没做完的后续段、而汇报没给提示词：按 `M13` 先问，来源线程本轮不 settle。两处都确认没有后续段、或交接线程已建好，才用 `t3_thread_organize`（`action:"settle"`，带来源环境的 `environmentId`）。

   收尾汇报里提到的遗留事项照抄进报告，并写明各自去向（登记文档、新建 issue 链接、交接线程）；汇报列了条目但去向里没有新线程、也没先问过提示词的，不算已有去向——按上面「缺提示词」先发给来源线程，来源线程本轮不 settle。
