# 回话模板

发给子线程的消息正文。判定表的「动作」列只写工具动作与模板编号，正文从这里取。

- 一律以 `【巡检】` 开头；`t3_thread_send` 带该环境的 `environmentId`、`mode:"auto"`。
- `<...>` 换成实际内容，其余照发；这些模板是代用户回话的口径，不自行增删要求。
- 模板里点名「不要等我确认」的地方是刻意的：这些线程常把该做的步骤挂起来等人批。

## M1 收敛路径未落地

触发：上一轮已发过收敛审计，PR 描述仍没有「交付范围」，或仍在逐条修范围外意见。

> 【巡检】收敛路径没有落地：你在 <审计时间> 做过方向审计，但 <PR 描述仍没有「交付范围」／仍在逐条修范围外意见，择实写>。请回到你账本里的顾问定性，由你直接执行，不要等我确认：本轮内按 pr-review-loop 把交付范围写进 PR 描述、拆出范围外改动、在账本记下收敛路径，然后再处理审查意见；范围外意见一律按 Consider 回复

## M2 收敛审计

触发：线程在 `convergenceAuditThreads` 里，且 24 小时内没发过收敛审计。

> 【巡检】收敛审计：<开了多久、多少意见、集中在哪些文件、最近的意见长什么样>。请暂停逐条修复，先派一位方向顾问独立看整份 diff（`route.mjs select --task design` 选人），按 pr-review-loop 方向审计的定性（有限清单/开放反例/范围扩张）给出结论；定性后本轮内直接把路径落地（PR 描述写交付范围、拆出范围外改动、账本记收敛路径），不要只给建议、不要等我确认，落地后再继续处理审查意见

## M3 空转打断

触发：`distinctRecentCommands` 小于 5，或 `minutesSinceLastMessage` 超过 60。先 `t3_thread_interrupt`，再发。

> 【巡检】你在重复执行同一类命令（例：<sampleCommand>），已打断。<查到的答案或判断>。下一步只做 <一件事>，不要再调查；同一条命令连续得到相同结果两次就换思路或下结论

## M4 换模型后继续

触发：连续两个 run failed，或报错是额度/上下文耗尽类。先 `t3_thread_configure` 换档，再发。

> 【巡检】已切换模型到 <model>，继续：<一句恢复要点>

## M5 同意按原任务继续

触发：它在请求原任务已覆盖的授权（提交、推送、建 PR、复审、重挂监听）。

> 【巡检】同意，按原任务继续，后续同类步骤不用再问

## M6 遗留项分流

触发：它在问遗留项怎么办（flaky、范围外缺陷、要不要跟进）。

> 【巡检】遗留项按性质处理：flaky 和基线问题记进仓库的登记文档（如 flaky 登记），之后统一处理；独立的问题在仓库用的问题追踪里各建一条（如 fast-ship issue），PR 汇报里附上链接；属于本需求后续段的才写交接提示词。处理完继续原流程

## M7 技术取舍按根治

触发：它在问方案、范围、修在哪个 PR、要不要结构整改。

> 【巡检】按根治方向：选长期更干净正确的方案，在当前 PR 内处理；账本或 PR 里已有顾问定性就照它执行，没有就先请一位方向顾问独立裁决（`route.mjs select --task design` 选人），与你的判断冲突时按根治取向自选，把结论和依据写进账本后接着推进

## M8 没关联 PR

触发：它说在等审查，但 `pullRequests` 为空或不含该 PR。巡逻侧本地有 `watch_pull_request` 时代挂，再发本条。

> 【巡检】本线程没有关联 PR #N，也没有挂 PR 监听，审查结论到了不会唤醒你。请用 `link_pull_request` 关联 <PR URL>，用 `watch_pull_request` 挂上审查与 CI 监听（工具不在列表里先用 tool_search 搜一次），然后立即重读最新审查意见与检查状态，按 pr-review-loop 继续

## M9 监听可能掉了

触发：`prs` 标了 `(stale)`；或线程 `completed` 停着、尾部自称在等，而 PR 最新结论晚于 `lastMsgAt`。

> 【巡检】监听可能掉了：重新读取最新审查意见与检查状态，按 pr-review-loop 继续，并重新挂上监听

## M10 收尾

触发：PR 已收敛（审查者通过、无未回报的审查请求、检查全绿，或尾部出现「等你合并」「ready for merge」这类收尾信号）。

> 【巡检】使用 $pr-finish 技能收尾

## M11 审查者复核超时

触发：触发发出超过 30 分钟仍无结论，评论/review 区没有新条目（上限跟 pr-review-loop「审查者现状」走）。

> 【巡检】<审查者>的复核似乎没回来（触发已过 X 分钟）。请 `gh pr checks` 确认检查状态；若仍无结果就重新触发一次，并说明如果长时间仍不回来就按收敛处理

## M12 瞬时失败继续

触发：run failed/interrupted/cancelled，但既不是连续失败也不是额度类。

> 【巡检】继续

## M13 索要交接提示词

触发：`$pr-finish` 收尾汇报的「交接后续工作」一项缺提示词（列了条目没给提示词，或既没提示词也没写「无后续段」），或任务书里有没做完的后续段。收尾汇报之外的消息不触发本条。

> 【巡检】按仓库约定的交接格式给出交接提示词（仓库没有约定就写一段可直接发给新线程的完整提示词），并写明在哪台设备上做

## M14 顾问复审收敛路径

触发：发过 `M1` 后收敛路径仍没落地，或路径落地后同一子系统又连续三轮有需修复的有效意见。

> 【巡检】收敛路径执行后仍未收敛：你在 <审计时间> 做过方向审计，之后又过了 <轮次> 轮、新增 <条数> 条意见。请把账本、上次定性和这几轮意见交给一位方向顾问复审（`route.mjs select --task design` 选人，与上次不同模型家族）：上次定性是否仍成立、要不要改判、是否需要设轮数上限或改交付范围。按复审结论本轮内落地并写进账本和 PR 描述，不要等我确认；复审前不要自定「只修某级别」这类规则

## M15 产品口径交顾问定案

触发：线程在等产品决策，原任务、issue、仓库约定和先例里都找不到答案，且不涉及删用户数据、动生产、强推。

> 【巡检】这个口径由方向顾问定，不等我：把问题、可选项、原任务与 <issue> 的目标交给一位方向顾问（`route.mjs select --task design` 选人），按「最贴合原任务目标、改动最少、可逆」裁决。结论写进 PR 描述「已定口径」和 issue，然后继续；若顾问判定需要删用户数据、动生产或改变已发布行为，停下来汇报选项、默认值和依据

## 无模板的两类

- **产品决策定案**：原任务或 issue 里有现成答案时，按依据自己定案，消息写「结论 + 依据出处 + 要它执行的动作」，格式自由。找不到依据就发 `M15`。
- **停滞推一把**：按尾部所指的那条规则选模板（M1–M15），不另写。
