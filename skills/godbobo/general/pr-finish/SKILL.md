# pr-finish

PR 已审查收敛，且已有合并、收尾或交付到主分支的授权时执行；授权可来自本任务早先指令，无需重复确认。与目标分支的整合在这里一次完成：对最新目标分支整合、验证、合并。

仓库特有的部分一律读仓库自己的文档（`AGENTS.md`、贡献指南、质量门禁文档）：检查入口、合并入口、合并方式、交接约定。仓库没有声明时用下文的默认做法。

## 步骤

1. **核对起点**：PR 为 OPEN，本地 HEAD 等于远端 PR head，工作区干净。有未提交改动（含上一轮已验证没推的修复）先按 `$git-prefs`「提交」处理并推送——它和下面两步的提交一样，是这次收尾要交付的受审提交。
2. **整合目标分支**：fetch 后把最新的 `origin/<base>` 合进当前分支（`git merge origin/<base>`）。仓库文档规定了整合方式就照它。默认用 merge：分支已推送、已审查，merge 只需把每处冲突解决一次，保留已推送的历史和审查评论的锚点。
3. **清理基线**：修掉目标分支带入、阻塞本次合并或构成重大风险的编译、lint、测试问题，与本 PR 的改动分开提交；其余低风险项按 `$pr-review-loop`「可合并标准」记录处置。提交并推送后跑仓库声明的合并前检查。完成标准：合并前检查在远端 PR head 上全部通过。
4. **等静默**：第 1 至 3 步的每次推送都触发新一轮审查，判据是推送本身而不是改动大小——保留 `$pr-review-loop` 的阶段、清单与验收历史，对新 HEAD 做增量核验和归桶跟进，有 Act on 修完再推，直到该技能「结束（静默）」成立；审查者超时按那里的「等待上限只花一次」记账跳过。意见按该技能「可合并标准」处置，低风险遗留不会单独重开修复循环。完成标准：静默的 HEAD 就是下一步要合并的 HEAD。
5. **合并**：用仓库声明的合并入口合并；没有声明时 `gh pr merge <号> --match-head-commit <HEAD>`，合并方式取仓库默认。合并的就是静默的那个提交：其间目标分支又前进了，回到第 2 步并重新等静默。完成标准：PR 状态为 MERGED。
6. **交接后续工作**：在仓库 `AGENTS.md` 和 `.agents/skills/` 里找交接约定（如 build-issue 类技能）。PR 汇报里有遗留事项、或需求还有其他端/阶段未做时，按约定输出交接提示词并写明交给哪台设备。遗留事项按性质分流：flaky 与基线问题记进仓库约定的登记文档，之后统一处理；独立的问题在仓库使用的问题追踪里各建一条；只有属于本需求后续段的才写交接提示词。完成标准：每条遗留事项都有去向（登记、条目链接或交接提示词），没有后续段时明确写「无后续段」。
7. **关闭关联问题**：PR 关联了问题追踪条目，且整条需求已经全部落地，按对应技能把它标为完成；需求还有后续 PR 时保持进行中。
8. **回收分支与工作树**：本技能被调用即视为用户明确要求删除当前工作树。
   - 删除远端分支（合并时已自动删除则跳过）；
   - 记下主仓库 git 目录（`git rev-parse --path-format=absolute --git-common-dir`）和当前分支名；
   - 当前在链接工作树里时：cwd 先切到工作树根，运行 `node <git-prefs 技能目录>/scripts/empty-worktree.mjs`（清空内容、保留目录壳，绑定此目录的 shell 继续可用），再 `git --git-dir <主仓库 git 目录> branch -D <分支>`。删工作树只用这个脚本：目录一旦消失，本线程的 shell 就永久失效。在主检出上则切回目标分支、拉取后删除本地分支。
   - 本机装了 T3 Code（有 `~/.t3/worktrees`）时，再跑 `$t3-code` 的 `t3-worktree-gc.mjs --purge-build` 预演，回收其他已终结线程留下的工作树和构建产物；结论确认无误后加 `--apply`。
9. **汇报**：合并提交、整合时解决的冲突与基线修复、收尾轮回报（哪个审查者、几轮、有没有 Act on）、交接提示词、关联问题状态、回收结果。
