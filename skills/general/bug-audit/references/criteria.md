# 审计准则

目标是报告生产可达、能写清触发路径的真实 bug，而不是罗列工具命中、风格问题或理论异常。

## 什么算

同时具备下面四点，才算可以写入报告的发现：

1. **固定证据**：证据 SHA、文件路径与行号对得上，描述与该处代码一致。
2. **生产可达调用链**：能从生产入口追到命中点，例如 HTTP / RPC handler、UI 事件、对外 CLI，或生产会执行的定时任务与脚本。
3. **前置条件与触发**：写清走到这条路径需要什么条件，以及具体输入如何变成错误结果（崩溃、错误数据、错误授权、敏感信息泄露等）。
4. **防护与语义已核对**：已阅读周边校验、错误处理、权限判断和框架默认行为；结论建立在读到的代码上，而不是「这类代码通常会怎样」。

关注的问题类型包括（不限于）：

- **逻辑错误**：条件反了、状态机漏迁、错误的默认值或短路、误用返回值。
- **输入边界**：空值、空集合、上下界、整数溢出、超长或畸形输入、分页与偏移。
- **错误处理**：吞掉错误后继续用无效结果、遗漏关键失败分支、把临时错误当成成功。
- **并发与资源**：竞态、重复释放或未释放、关闭后仍使用、超时与取消未传递、泄漏或死锁。
- **持久化与协议**：损坏或丢失写入、错误的幂等与重试、序列化/版本不兼容、请求响应错位。
- **安全**：鉴权缺失或绕过、授权/越权、注入、敏感信息进入日志或响应、不安全反序列化等。安全项必须另见下方门槛。

## 什么不算

- 纯风格、命名偏好、缺注释，或「理论上可能抛异常」但没有具体触发路径。
- 测试、示例、生成代码、vendor 或第三方拷贝中的命中。它们默认不是生产路径。
- 工具、规则或 lint 命中但语义不符：例如已被校验挡住、框架已经处理、或调用约定保证不会走到。
- 非安全用途的哈希或普通随机，例如 checksum、缓存键、展示用乱序、非安全抖动；不要把 `md5` / `math.rand` 一类用法自动报成安全问题。
- 没有可信威胁模型、也说不清外部可控性的「可能的安全问题」。
- 既没有具体输入到错误结果，也追不到生产调用链的词法命中。

脚本、运维或工具目录里的代码，**不能只因为后缀是脚本就排除**。若它会被生产定时任务、发布流程或线上运维实际执行，仍按生产路径核实。

## 线索、工具与覆盖

词法搜索、规则或 lint 命中只是线索，必须打开代码核对调用链、触发和已有防护。环境里没有对应工具时，用搜索和阅读即可，不要为此安装工具、锁定版本，或补一套扫描后端。

静态检查是可选的。仅当当前环境**已经有**相应工具，并且能以不改被扫仓库、不安装依赖或工具链、不运行 `npm ci` 以及其它会隐式写入或执行不受信构建脚本的方式运行时，才把结果当作线索。不要为了跑检查去启用 CodeQL，或安装 Android SDK、Gradle、Xcode、DevEco 等工具链。常用而可选的线索来源包括语言自带检查、semgrep 及已有规则集、以及环境里已存在的 linter；跑不出或不跑都可以，不影响只靠阅读做完本技能。

覆盖按本轮范围和当前环境里实际能用的手段合理安排，不必每种语言、每一条规则都跑到。在报告里写明已看方向和未覆盖处。结论限定为「在所述范围和方法内发现或未发现」，不以找全问题为完成标准，也不能写成「没有 bug」。

## 防护、部署与服务端输入

- **核实，不要假设。** 「通常有中间件」「框架默认会校验」「部署层会做 TLS」都不能直接当作已防护，除非在本仓库代码或本轮能核验的配置里看到了对应行为。
- **部署未知就标限制。** 不知道网关、权限模型或运行环境时，写明这一限制；不要把未知夸大成已证实的外部可利用，也不要仅仅因为部署情况不清，就丢掉已经能在代码里证实的逻辑错误。
- **不要机械丢弃服务端输入上的逻辑错误。** 输入由服务端拼接或内部产生，可能使某类「攻击者可控」的安全问题不成立，但逻辑错误、崩溃、错误写入或错误授权仍可能成立。要按问题类型分别判断，而不是一律丢弃。

## 安全项的额外门槛

安全类发现除满足「什么算」之外，还要同时写清：

- **可信威胁模型**：谁、在什么入口、想得到什么；不是套用漏洞名称。
- **外部可控性**：攻击者或外部调用方如何影响触发输入或控制流。不可控则通常不应报成安全问题，但仍要检查是否构成逻辑或可靠性缺陷。

日志、密钥、token、证件号或其他敏感证据在报告和复现说明里必须脱敏。可提供受控、离线的最小复现指引（本地测试、固定夹具、最小输入样例）；不得指导对线上系统、真实账户或真实数据发起攻击。

## 严重级（按实际影响、可利用性和概率）

不要因为「这是安全问题 / 这会崩溃」就自动定为 P0。依据已经核实的触发条件、影响范围、利用难度和发生概率来评；证据撑不住就向下评，不要往上靠。

- **P0：** 在已核实的生产路径上，较容易被触发，且会造成严重后果，例如可利用的远程代码执行、明确的越权或鉴权绕过、大范围敏感数据泄露、生产数据损坏或丢失，或常见输入下几乎必现的严重故障。
- **P1：** 真实生产路径上后果明确，但利用条件更苛刻、影响更局部，或主要造成错误结果、较难触发的崩溃、资源泄漏、有限的敏感信息泄露。
- **P2：** 边界条件下的真实缺陷、会变成静默失败的错误处理缺失，或影响有限的加固问题；有具体触发，但严重程度或概率都较低。

## 低置信线索

达不到正式发现门槛、但仍值得提醒的线索，可列入报告附录，最多 5 条，标明待确认。没有这样的线索就不要凑。
