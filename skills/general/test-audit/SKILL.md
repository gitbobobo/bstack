# test-audit

以**行为契约**衡量测试价值：它保护什么，哪种错误实现必须让它变红，以及为此付出的反馈成本。默认只读审计；扫描由代码搜索、项目现有工具和追踪源码完成，不以词法命中自动定罪或删除。

## 1. 定范围与预算

读项目约束，记录仓库、HEAD、dirty 状态、审计目标（全项目或指定范围）与本轮预算：深读范围、允许的命令类别、最长执行时间/重跑次数。未给预算时先做静态审计，优先共享夹具与高影响候选，剩余列为未覆盖。

- 默认允许读取、搜索、只读 git 查询。项目 lint/check/list 先审阅入口、配置和模块顶层代码，确认副作用与资源成本后才执行；收集也可能加载代码。
- 定向测试、性能对照或重现属于显式选择的验证阶段，先限定目标集和预算，遵守项目调度入口。全量重跑、设备测试、压力测试不作为默认扫描步骤。
- 默认给修改建议；修改测试、生产代码、lint 配置或临时注入故障，均需修复授权。对外部/attach 服务的状态写入另核所有权与许可。

完成：报告有基线、范围、执行许可和预算；已有改动保留，未擅自同步/切换目标仓库。

## 2. 画执行地图

从 manifest、runner 配置、统一脚本、本地门禁与 CI 追出每条实际入口，包含内联测试、工具脚本测试、契约/集成/设备测试和手工注册。按**执行器及配置**区分，不按语言复制审计流程；同一语言也可能有不同进程和隔离模型。

每个 runner 按 [适配六问](references/runner-adapters.md) 记录发现方式、skip 语义、并行/状态边界、时钟、资源清理和现有 lint。先读已有卫生基线、哨兵、失败事实记录与近期修复决策，区分存量债务和新增缺口。

执行证据分别标注：

| 标签 | 所见证据 | 结论边界 |
| --- | --- | --- |
| 声明 | scripts/config/文档 | 声明运行哪些测试 |
| 收集 | 实际 list/collect 输出 | 此入口收集到哪些测试 |
| 执行 | 对应版本的原始报告 | 此次实际执行的通过/失败/跳过与耗时 |
| 强制 | hook/gate/合并约束及执行证据 | 哪些改动被要求运行哪些测试 |

声明不能证明执行，门禁存在也不能证明本次已执行。历史报告单列来源、版本与时间；覆盖率注明 include/exclude 的测量范围。无远端 CI 本身不是缺陷，检查实际验证链覆盖了哪些 runner 与改动类型。

完成：每条已发现入口有归属、配置和证据标签；无法定位或未确认执行的入口明确标记。

## 3. 广扫与深读

按下面七类建立 **runner × 类别** 台账，逐格记录搜索方法/候选数、深读文件数及分母，或“未覆盖及原因”。数字注明文件名匹配、词法计数、下界等口径；同一文件可能属于多个运行配置。

| 类别 | 扫描问题 |
| --- | --- |
| 执行失真 | 漏收集、配置漂移、静默早退、失败被吞或结果过期？ |
| 环境失真 | 替身、fixture、依赖与配置是否偏离契约所在的真实环境？ |
| 断言失效 | 所称契约被破坏时，断言仍然通过？ |
| 实现耦合 | 锚定的是内部写法，还是必须保护的结构/边界？ |
| 非确定性与隔离 | 结果受顺序、时间、随机、共享资源或环境影响？ |
| 成本错配 | 开销能否在保留同等保护下显著降低？ |
| 冗余与失效覆盖 | 是否重复同一风险，或保护已退休的契约？ |

按 [判据与误判陷阱](references/criteria.md) 选择项目适用的搜索线索。排除依赖/构建产物；配置与共享 helper 仍要纳入。

每个 runner 优先深读共享 setup/helper/fixture，再看最大或近期高频修改文件、候选集中处，并抽查少量未命中文件验证搜索盲区。没有共享 setup 就记录“不适用”；预算不够就记录未读，不能据此宣称整套测试无问题。

完成：台账无空格，抽样理由和未覆盖项可核查；候选能定位到文件，而非只列计数。

## 4. 追踪与裁决

每个高影响候选追踪 **测试 → helper/替身 → 生产入口 → 契约或历史决策**，写一句：“保护 X，出现 Y 错误应变红”。一个根因只报一条发现，多种后果写入影响。

- 区分源码可直接确认的事实、机制推断和待运行验证。指出具体假绿/假红反例，同时找合理例外与已有缓解。
- 涉及替身/fixture：列“测试值、真实值、差异理由、是否影响本契约”，包括协议属性、默认配置与依赖可用性。对齐生产不是目标，**保留契约所需的真实性**才是。
- 涉及时间：先分正向等待、负向观察窗口、业务时限，并判断时序归测试假设、产品契约还是运行环境。负向断言改成首次满足即结束的轮询会漏检；详见判据。
- “慢”需阶段耗时及累计/关键路径影响；没有测量就报成本候选。“flaky”需同一源码和配置下结果不稳定的运行或历史证据，记录失败签名与环境差异；不稳定不等于测试有错，真实产品竞态分流给产品修复。
- 证据不足时给最小补证命令和预算，保留待验状态。执行过的命令记录目录、版本、环境、退出码、原始日志路径及遗留进程/资源。

完成：每条发现有契约、因果路径、证据等级、例外与动作，不以 sleep/mock 数量推导失败率或耗时根因。

## 5. 输出建议与防复发

动作按证据选择：**保留／保留并说明边界／局部加固／重写或移层／删除**。参照 [动作门槛](references/criteria.md#动作门槛)：删除必须说明契约已退休，或逐条有效断言由哪些具名测试与断言替代；唯一可执行的回归保障先补替代再删。未执行的测试先报告执行缺口，再讨论价值。

重写建议保留边界、负面场景与历史回归意图，说明如何验证“正确实现绿、代表性错误红”。有修复授权且成本可控时执行红绿验证并恢复临时注入；否则只提供方案并标为未验证。前后性能对照使用相同配置、覆盖与可比环境，计入 setup/收集/构建成本；几次通过不能证明消除 flaky。

按 [lint 门禁](references/lint-gating.md) 为每类根因判断：现成规则、自定义规则、运行时守卫，还是仅能人工审查；没有可靠防线也如实说明。

报告包含：

1. **范围**：基线、runner 地图、执行证据、覆盖台账、口径与未覆盖项。
2. **发现**：优先级及依据；`path:line`；类别；事实/推断/待验；保护契约；具体失败机制、例外和已有缓解；动作与门槛；替代测试位置；最小验证。
3. **防复发**：工具/规则、版本核验状态、适用范围、正反例、豁免与渐进接入方式；未运行的不写成已通过。
4. **排除项与限制**：哪些怀疑经追踪不成立，依据是什么；剩余补证与资源清理情况。

完成：按错误放行/误阻塞风险和已知反馈成本排序，合并重复根因；结论限定为“在所述范围和方法内发现/未发现”，不输出无依据的健康评分。
