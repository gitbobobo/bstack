# 防复发：把可靠规则变门禁

## 选择防线

每条建议先回答：能静态确定吗？需要运行时资源/注册证据吗？还是必须理解行为契约？只有前两种适合机械门禁，第三种保留为审查线索。

| 候选防线 | 可门禁的前提与边界 |
| --- | --- |
| focused/only、无理由 skip/ignore | 确认项目不允许提交这些状态，识别真实框架调用，允许带理由的正当分层 |
| 悬空 Promise/异步断言 | 按框架与类型信息核验；合法的后台任务必须有明确所有者及完成/取消协议 |
| runner 文件认领/手工注册检查 | 与实际收集器对照；允许声明的多配置矩阵及平台排除，检查截断/漏注册 |
| 必需依赖 preflight、报告新鲜度/失败退出码 | 必需套件缺依赖失败，可选套件显式记录未执行；检查本次源码/配置/runId，而非 grep 出几个 SKIP 字符串冒充计数 |
| 生成物漂移/结构化依赖边界 | 对真实工具输出或解析结构检查；为误报与绕过写测试，不将函数体文本当业务语义 |
| 资源泄漏守卫 | 按资源类型、进程及清理作用域检查，给异步收敛明确界限；避免把后台运行环境的合法资源当泄漏 |
| 固定等待限制 | 先提供正向等待与负向窗口两种正确替代，再限制目标 API；真实 I/O 和设备等待支持带理由豁免 |
| 基线约束 | 按规则与条目标识比较新增/删除，单看总数不够；报告数量与变化，理由及复审方式可追踪 |

## 优先复用项目工具

检查已有 lint/runner 插件、锁定版本和规则文档，输出**已核实的规则名与范围**；否则标“候选工具，尚未核验”，不提供假装可直接复制的配置。

可调查的方向包括：JS/TS 的框架 ESLint 插件与类型感知异步规则（如 `@typescript-eslint/no-floating-promises`）、Playwright 插件；Rust 的 Clippy 与仓库自定义约束；Go 的 vet/测试相关 analyzer；其他运行时的框架插件与静态检查。它们不能通用地证明 fixture 语义一致、资源必定关闭或测试确实有价值。

只有现成工具不覆盖而规则稳定时，建议一个小的 AST/配置检查；须测试违规样本报错、合法样本不报、配置范围正确。跨语言正则库和“坏测试评分”不作为默认交付；词法扫描可以做低成本线索或窄策略门禁，但要显式说明注释/字符串/别名等误判边界。

## 接入顺序

1. **核验**：确认工具版本、规则名、目标文件及现有配置兼容性；列出替代写法。
2. **试跑**：获准后在目标范围运行，统计具体违规与误报，检查正确用法及已知例外。没有运行就记录待验。
3. **收敛**：优先修共同根因；必要时建立逐项基线或增量门禁，已入基线不等于已修。豁免写理由，责任人与复审日期/触发条件按项目惯例选择。
4. **接入**：只有规则可靠、替代可用、例外可解释时才接已有 lint/gate；说明新增成本，不默认新增 CI 系统。需要执行证据的检查接入 runner/报告链，而非强塞进源码 lint。

## 保留为审查线索

弱断言、mock 密度、影子算法、源码文本断言、巨大文件、sleep 次数、fixture 相似、测试/生产比例，以及未追踪所有者的“未关闭资源”，都不能直接决定删除或阻塞。

“文件里存在 expect”的规则至多发现部分缺断言，抓不到断言对象偏离契约；“环境变量加锁”的规则也抓不到未协作的读者。报告必须区分**语法卫生门禁**与**行为保护证据**。
