# pr-finish

PR 已审查收敛，且已有合并、收尾或交付到主分支的授权时执行；授权可来自本任务早先指令，无需重复确认。与目标分支的整合在这里一次完成：对最新目标分支整合、验证、合并。

仓库特有的部分一律读仓库自己的文档（`AGENTS.md`、贡献指南、质量门禁文档）：检查入口、合并入口、合并方式、交接约定。仓库没有声明时用下文的默认做法。

## 步骤

1. **核对起点**：PR 为 OPEN，本地 HEAD 等于远端 PR head，工作区干净。有未提交改动（含上一轮已验证没推的修复）先按 `$git-prefs`「提交」处理并推送——它和下面两步的提交一样，是这次收尾要交付的受审提交。
2. **整合目标分支**：fetch 后把最新的 `origin/<base>` 合进当前分支（`git merge origin/<base>`）。仓库文档规定了整合方式就照它。默认用 merge：分支已推送、已审查，merge 只需把每处冲突解决一次，保留已推送的历史和审查评论的锚点。
3. **清理基线**：修掉目标分支带入、阻塞本次合并或构成重大风险的编译、lint、测试问题，与本 PR 的改动分开提交；测试失败先按 `$pr-review-loop`「测试失败处置」分诊、处置，其余按该技能「分级」记录。提交并推送后跑仓库声明的合并前检查。完成标准：远端 PR head 的必需检查实际通过，隔离项按该处置规则单列。
4. **收尾复核**：第 1 至 3 步推送触发的审查沿用 `$pr-review-loop` 的账本与预算，轮数不重置。只核对这次整合和基线修复带来的改动：其中的 blocker 修完再推；其余按该技能「分级」回复，不为它开新的修复轮。无冲突、未改代码的整合只等检查通过。审查者超时按「等待上限只花一次」记账跳过。完成标准：要合并的 HEAD 上检查通过、没有未关闭的 blocker、新意见都已回复。
5. **合并**：用仓库声明的合并入口合并；没有声明时 `gh pr merge <号> --match-head-commit <HEAD>`，合并方式取仓库默认。合并的就是第 4 步复核过的提交。其间目标分支又前进了：合并入口允许（无冲突、不要求分支最新）就直接合并；要求最新时回到第 2 步，无冲突的整合只等检查。记录因目标分支前进而被迫重整合的次数；在 T3 环境连续两次，或同仓库最新 PR 编号差大于 20 且已发生一次时，使用已安装的 `$t3-code`「收尾窗口」申请协调后再继续。未安装该能力时汇报循环原因与需要的串行收尾窗口。完成标准：PR 状态为 MERGED。
6. **分流遗留与交接**：先按 `$pr-review-loop`「改动准入」逐项裁决；候选记重启条件，不采纳项写依据，二者都不生成执行任务。已准入的独立缺陷按仓库约定登记并查重；本需求仍有必须交付的其他端/阶段时，再从仓库 `AGENTS.md` 和 `.agents/skills/` 读取交接格式，给出提示词与目标设备。跨端先证明行为/契约缺口，单纯验证可把证据补到原 PR/issue；只有有价值的代码、测试或持久文档变更才需要新 PR。测试遗留项沿用 `$pr-review-loop`「测试失败处置」的后续安排。完成标准：每项都有准入结论与去向；没有已准入的后续段时明确写「无后续段」，留下候选不影响收尾。
7. **关闭关联问题**：PR 关联了问题追踪条目，且整条需求已经全部落地，按对应技能把它标为完成；需求还有后续 PR 时保持进行中。
8. **回收分支与工作树**：本技能被调用即视为用户明确要求删除当前工作树。
   - 删除远端分支（合并时已自动删除则跳过）；
   - 记下主仓库 git 目录（`git rev-parse --path-format=absolute --git-common-dir`）和当前分支名；
   - 本任务另建过的辅助工作树（基线截图、对照、复现用的 `git worktree add`，`git worktree list` 里除当前树之外由本任务创建的）逐个 `git worktree remove --force <路径>`，再 `git worktree prune`；
   - 当前在链接工作树里时：cwd 先切到工作树根，运行 `node <git-prefs 技能目录>/scripts/empty-worktree.mjs`（清空内容、保留目录壳，绑定此目录的 shell 继续可用），再 `git --git-dir <主仓库 git 目录> branch -D <分支>`。删工作树只用这个脚本：目录一旦消失，本线程的 shell 就永久失效。在主检出上则切回目标分支、拉取后删除本地分支。
   - 本机装了 T3 Code（有 `~/.t3/worktrees`）时，再跑 `$t3-code` 的 `t3-worktree-gc.mjs --purge-build` 预演，回收其他已终结线程留下的工作树和构建产物，以及扫描根之外被遗忘的 detached 临时工作树；结论确认无误后加 `--apply`。
9. **汇报**：合并提交、整合时解决的冲突与基线修复、收尾复核结果（哪个审查者、几轮、有没有 blocker）、交接提示词、关联问题状态、回收结果。
