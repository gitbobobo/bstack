# 历史（可选）

历史用来避免同仓同类重复报告，并分清「已经告诉过用户」和「已经成功建成 issue」。它不是运行框架：不要为此编写启动器、调度器、批处理清单或固定目录布局。

## 从哪里读

只使用本轮用户或调用方指定的历史文件，或调用方已经在维护的状态。没有指定时不要假设本机默认路径，也不要在技能里写死某个目录、仓库清单或项目 ID。

读到后先按仓库过滤，再按规范化类别（并对照模式名称与一句话摘要）判断是否同类。已被报告过的同类不要再当作新发现；其中已有核验过的 issue 编号的视为已建，不要再创建一张。

若指定的文件不存在，视为尚无历史，可以继续扫描。若文件存在但无法解析为预期结构：不要改写或覆盖它，向用户说明后继续只读工作（需要写入时则停止写入）。

历史文件里可能已有 `reported` 数组。兼容这些常见字段：`repo`、`date`、`pattern`、`category`（可能缺失）、`summary` 或 `description`、`evidence`（路径或带 SHA 的链接）、`sha`（可能缺失）、`issue`（仅当曾经成功建单时出现）。缺失的类别根据模式名称和摘要做就近判断，不要因为旧记录没有 `category` 就重复报一遍明显同类的模式。

## 写什么

仅在调用方希望保留历史、并且已经指明写入位置（历史文件或调用方状态）时才写。报告完成、且建单（若已授权）已经尝试结束后再追加。

每条新记录至少包含：

| 字段 | 说明 |
| --- | --- |
| 日期 | `YYYY-MM-DD`，并注明时区 |
| 模式名称 | 报告里用的短名 |
| 规范化类别 | 用于同仓去重的稳定类别 |
| 一句话 | 摘要（建议字段名 `summary`） |
| 证据 SHA 与文件 | 本轮证据 SHA，以及各处路径/行号或带 SHA 的链接 |
| issue 编号 | 仅当本轮创建并回读成功时写入，例如 `INT-123` |

推荐追加到顶层 `reported` 数组，字段名与上表对应：`repo`、`date`、`timezone`、`pattern`、`category`、`summary`、`sha`、`evidence`、以及可选的 `issue`。不要发明第二套并行账本，除非调用方已有自己的状态格式——那时按对方格式追加同等信息即可。

必须区分：

- **已报：** 本轮已向用户报告。只要报告已经发出（交互式已说明，或自动调用因有新模式而给出了报告），就可以追加一条，即使尚未建单。
- **已建：** 仅当 `$fast-ship` 创建成功并且回读确认标题与正文无误。只有这时才写 `issue`。

创建失败、回读失败、被查重跳过或本轮未获建单授权：可以记已报，但不得填写 issue 编号，也不得用其它方式标成已建。否则以后会当成已经建过而不再补单。

未找到可信新模式、因而没有报告内容可记时，不要追加空记录。

## 怎么写才算安全

- 先读后写，只追加本轮新记录，不得重写、删除或改写已有条目。
- 文件已存在但解析失败：停止写入，保留原文件。
- 写入时尽量原子替换（例如写到同目录临时文件再改名），避免写到一半留下损坏文件。
- 不要为了「方便下次运行」创建调度配置、默认仓库清单或硬编码的本机路径。
