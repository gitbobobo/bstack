# 审计准则

目标是报告真实热路径上能说清代价的性能问题，而不是罗列工具命中或理论优化。

## 什么算

同时具备下面三点，才算可以写入报告的发现：

1. **入口调用链**：能追到请求 handler、应用启动、UI 渲染/列表，或遍历用户数据的循环。
2. **规模或频率**：循环或结构处理的是什么数据、大约多大，或该路径多常被走到（用户数据量、分页上限、启动次数、滚动/重绘频率等）。
3. **明确代价**：能说明触发后会发生什么，例如额外的查询/网络次数、主线程或事件循环被阻塞、重复计算或拷贝的量、内存是否无界增长。

关注的问题类型包括（不限于）：N+1 与循环内串行 I/O 或 await、循环内重复计算或重复编译、热路径 O(n²)、同步阻塞（含主线程/事件循环上的 I/O 与启动重活）、无界内存增长、列表渲染（缺稳定 key、未懒加载或未复用）以及冷启动同步重活。

## 什么不算

- 固定小 n：常量小数组、固定枚举、几个元素的配置表。
- 不在热路径上：一次性脚本、迁移、测试、示例、生成代码、vendor 或第三方拷贝。
- 已经用缓存、批量、分页或并发避开该代价的实现；最多降级，不要再当新的严重问题。
- 工具或规则命中但语义不符。例如每个元素只拼接一次、并不是在同一缓冲区上累积；或 defer 实际写在循环里新建的闭包中、会按次释放。
- 只有模式名称、没有规模和代价的「可能较慢」。
- 虚构的耗时、QPS 或 benchmark 数字；未做测量就写成「卡了 N 毫秒」。
- 范围大到不可控的「整体重写」或纯风格偏好。

## 线索与语言方向

词法搜索、规则或 lint 命中只是线索，必须打开代码核对调用链与规模。下面是常见线索，不是自动定罪清单；环境里没有对应工具时，用搜索和阅读即可，不要为此安装工具或锁定版本。

- **通用：** 循环或批量路径里的数据库/HTTP/RPC 调用、同步 I/O、无界缓冲或无限增长的缓存、启动与首屏路径上的重活。
- **Go：** 循环内字符串 `+=`、循环内 `defer`、在请求路径或循环里编译正则、handler 内按元素逐次查库。
- **Rust / Python / JS/TS：** 循环内 await 或 ORM/HTTP 调用、同步 `fs`/`exec`、循环内 `find`/`indexOf`/`includes`/`filter`/`sort` 造成的 O(n²)、`JSON.parse(JSON.stringify(...))` 深拷贝、明显多余的 clone/collect。若环境已有 clippy、语言 linter 或性能规则集，可作线索，失败或缺失就跳过。
- **Kotlin (Compose)、ArkTS、Swift：** `LazyColumn`/`LazyRow` 的 `items` 缺 key、`ForEach` 未用懒加载或缺 key、列表项未复用、`body`/Composable/`build()`/`aboutToAppear` 内的重计算或同步 I/O、不稳定的 `List` 参数、循环内新建 `DateFormatter` / `NSRegularExpression` 等。这些框架特征**不是**一命中就报告：必须能说明在真实数据规模或频繁重组下的代价。

可选的自包含 semgrep 规则见 [rules.yml](rules.yml)。仅当当前环境已经有 semgrep 或兼容工具时使用，加项目里合理的排除（如 `vendor`、`node_modules`、生成文件、压缩脚本和第三方静态拷贝）。跑不出或不跑都可以，不影响只靠阅读做完本技能。

## 测量与推断

- **测量：** 来自本轮能读到的 profile、trace、日志或已有基准；写明来源，不要改写或补造数字。
- **推断：** 按复杂度、调用次数、数据规模或阻塞位置作出的判断，必须标明「推断」，并写出依据。
- 两者都没有、又说不清规模与代价：不要写成正式发现。

## 严重级（按真实影响，不按模式名称）

不要因为「这是 N+1 / 主线程 I/O」就自动定为 P0。依据已经核实的触发条件、规模和代价来评；证据撑不住就向下评，不要往上靠。

- **P0：** 有证据表明在真实热路径上会造成严重的用户可见或生产故障级影响，例如请求或启动路径被数据量放大到可能卡住、ANR、OOM，且触发条件与规模说得清。
- **P1：** 真实热路径上有明确、可感知的代价（明显掉帧、高频路径上的串行 I/O 或 await、冷启动同步重活），但尚未达到故障级。
- **P2：** 真实路径上局部可量化的浪费（循环内重复编译正则、多余拷贝、字符串累积拼接等），影响有限。

## 覆盖

按本轮范围和当前环境里实际能用的手段合理覆盖，不必每种语言、每一条规则都跑到。在报告里写明已看方向和未覆盖处。结论限定为「在所述范围和方法内发现或未发现」，不以找全问题为完成标准。
