---

核对仓库里**实际存在的生态**中的**直接依赖**：区分声明范围与锁版本，向对应 registry 查询最新稳定版，按「立即升级 / 可以升级 / 暂不动」分档，查不到的标「未核验」。版本与漏洞结论只取本轮查到的结果。默认只读：只出报告，被扫仓库的清单与 lockfile 保持原样，任何包都不安装、不升级，不提交。

## 1. 范围与基线

范围取用户本轮指定的仓库、路径或生态，缺省为当前工作区。记下仓库标识（`owner/name` 或本地名）和 HEAD **SHA**，清单、锁文件与版本结论都以该 SHA 为准。

## 2. 探索

按 [审计准则](references/criteria.md) 与 [生态与查询](references/ecosystems.md) 探索。用户指定了生态或包就沿该方向；否则先盘点该 SHA 下实际存在的清单与锁文件，只核对出现过的生态的直接依赖。registry 访问失败、或私有源需绕过授权才能查的，标未核验。

## 3. 核实

- **范围真实：** 包确实在该 SHA 的清单或锁文件里；写清声明范围与锁版本（没有锁文件写「无锁」）。间接依赖、工具插件、构建依赖、工作区内部包与版本目录/BOM/constraints 各自归组，不混进运行时直接依赖。
- **版本真实：** 最新稳定版来自本轮实际查询（注明抓取日期、时区与 URL 或查询方式）；预发布版只在项目已跟预发布线时算，并写明。
- **漏洞与弃用有权威来源：** 指向官方公告、OSV、GHSA 或同等通告，核对受影响区间覆盖实际锁版本并给出修复版本；落后版本数、星标、下载量不是安全证据。
- **分档站得住：** 按准则分档；跨多个大版本要同时说明收益和迁移成本才进「立即升级」；建议给最小修复版本与可行目标。

**完成标准**：报告里每条都过了这四关；未覆盖的生态在报告里写明。

## 4. 报告

中文报告，允许零发现：

1. **范围**：仓库、证据 SHA、覆盖的生态与清单/锁文件，未覆盖或未能核对的部分。
2. **结论表**：按生态分组，每行写包与声明范围、锁版本、最新稳定版、建议版本、分档、证据、约束（MSRV / SDK / runtime / 平台 / 许可证 / peer）、升级验证建议。git / path / vendor 等无 registry 的依赖单列。
3. **分档摘要**：立即升级、可以升级、暂不动、未核验的要点；立即升级项写清依据。

结论限定为「在所述范围和方法内的核对结果」。
