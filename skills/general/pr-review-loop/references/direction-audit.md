# 方向审计

同一 blocker 修两轮仍复发、修法来回反转，或每轮都从同一机制冒出新 blocker 时读取。目的不是再找一遍问题，而是决定「接着修、换机制，还是收窄范围」。

派一位不同模型家族的只读方向顾问：编排环境用 `$t3-orchestrator` 的 `--task design` 选人，否则用 harness 子代理。传 PR 意图、整份 diff、账本与历轮回复、原始验证证据；复审额外传上次结论和之后的实际结果。

顾问给出一种定性：

- **有限清单**：方向成立，剩余 blocker 可枚举。逐项编号，附因果证据与验收条件。
- **开放反例**：同一机制不断产生新反例。换掉这个机制，或在满足意图的前提下收窄支持范围。
- **范围扩张**：新问题主要来自修复扩出去的行为。对照意图拆掉或另交付范围外部分。

由你按证据选定并落地：PR 描述更新意图与范围，账本记下定性、清单和取舍，范围外改动拆出或写明保留理由，换机制时完成实现和验证。顾问意见与你相反时，先把双方前提摆出来用代码或实验核对。

审计不重置轮数，也不追加预算：落地后的复核仍在原预算内进行，用完按 SKILL.md「预算」处理。
