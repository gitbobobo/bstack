# PR 写入隔离

创建 PR、更新描述、发表评论或提交 REST 请求体时，按以下顺序执行。工作树隔离不了系统临时目录；固定文件名会让并行线程读到彼此的正文。

1. **独占路径**：每次写请求用系统临时目录的原子唯一分配创建独占目录（POSIX `mktemp -d`，跨平台可用 Node `fs.mkdtempSync`）。正文、JSON 和辅助脚本都放在该目录内，用绝对路径引用。目录内可用 `body.md` 等固定名；隔离来自目录的随机后缀，只有 PR 号、分支名或线程号的固定路径不足以隔离重试和子任务。记录目录归属，消费完成前保持内容不变。
2. **绑定目标**：正文与请求体写成 UTF-8 无 BOM 文件；提交前读回，核对需求、标题和当前 diff。创建时显式指定仓库、head、base；更新时显式指定仓库及 PR 号或完整 URL，并核对远端 head 分支属于本任务。宿主命令与参数以本机帮助为准，始终引用本次分配的文件。
3. **回读确认**：写请求成功后，从返回的 PR 或评论 URL/ID 回读，核对仓库、PR head（创建或更新描述时）以及正文与本次提交内容一致，才算完成。重试同样经过目标核对与回读；发现不一致时保存本次文件、请求目标和远端结果，先定位原因再更正。消费结束只清理本次拥有的文件；失败取证材料保留到问题解决。
