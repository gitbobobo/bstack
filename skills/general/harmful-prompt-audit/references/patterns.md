# 有害提示模式库

每条模式一个小节，格式固定：

- **典型措辞**：搜索线索，中英文都列。
- **危害机制**：agent 读到后会怎样做，为什么比默认差。
- **例外**：看起来像、但不算有害的用法。
- **改写方向**：用正面陈述写出目标行为。

新增一类时，复制下面任一小节的结构。

## 创可贴诱导

要求"最小改动""最快修复"，把一次性的时间取舍写成 agent 的默认偏好。

**典型措辞**：最小改动、最小修复、尽量少改、改动越少越好、快速修复、先绕过、临时方案、能跑就行、不要重构、不要过度设计；smallest / minimal change、minimal diff、quick fix、just make it work、hack around、workaround、don't refactor、avoid over-engineering。

**危害机制**：

- agent 把"改动小"当成首要目标，放过根因，只在症状处打补丁。
- 补丁留在仓库里成为样例。下一个 agent 遇到类似问题会照抄这个写法，补丁模式逐渐扩散到各处。
- 手写代码时代选创可贴是因为没时间修根因；agent 改变了这个成本，常驻规则却仍按旧成本做取舍。

**例外**：

- **范围约束**，而非深度约束：例如"不要顺手改无关代码""一个 PR 只做一件事"，限制的是动到哪些地方，不限制对问题本身修得多深。
- 带明确理由和时限的场景：发布冻结期的 hotfix、不归本仓库所有的代码、线上止血且根因已另行跟踪。
- "不要过度设计"指向的是投机性抽象（为想象中的需求加扩展点），而非放弃修根因。需读上下文区分。

**改写方向**：写出要的行为，例如"修复问题的根因，即使改动更大；与问题无关的代码保持原样。根因修复需要跨模块或破坏兼容时，先说明方案和代价再动手。"确有止血需求时，写明场景，并要求同时记录根因和后续修复去向。
