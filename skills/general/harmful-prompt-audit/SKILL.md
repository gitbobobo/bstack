# harmful-prompt-audit

**有害提示**：agent 会读到的一段文字，系统性地把产出推向比默认更差的方向。危害随两样东西放大：**常驻**（每轮都加载，如 `AGENTS.md`、规则文件、技能 description）和**传染**（它催生的代码或文字成为仓库样例，被下一个 agent 照抄）。

已知的有害类型收在 [模式库](references/patterns.md)，每类一条，含搜索线索、危害机制、例外与改写方向。模式库是唯一判据来源；本文件只管流程。

默认只读：输出报告和改写建议，用户授权后才改文件。

## 1. 圈定 agent 读物

找出仓库里所有 agent 会读到的文字，按加载方式分三档记录：

- **常驻**：`AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`、`.github/copilot-instructions.md`、`.windsurfrules` 等 harness 规则文件，技能 frontmatter 的 description。
- **按需**：技能正文与其 references、被常驻文件指向的文档。
- **生成**：代码里拼给模型的提示词模板、派活/编排脚本里的任务 brief、issue/PR 模板（常被直接转给 agent）。用 `rg` 找 `prompt`、`system`、`instructions`、`brief` 等变量名和多行字符串定位。

用户指定了路径就只扫那里。排除依赖目录和构建产物。

完成：三档各列出了具体文件清单，或注明该档在本仓库不存在。

## 2. 按模式库广扫

对模式库里的**每一条**，用它的搜索线索在第 1 步的文件里搜（中英文措辞都搜）。命中只是候选，词法命中不定罪。

完成：每条模式都执行过搜索，记录了命中数；零命中也记下来。

## 3. 逐条裁决

读每个候选的上下文（所在段落、所属文件的用途、它约束的对象），对照该模式的「例外」判断：

- **成立**：写出具体机制，即 agent 读到它后会怎样做、为什么比默认差。
- **例外**：说明命中了哪条例外。
- **存疑**：缺少判断所需的上下文（如不知道某规则是否只在发布冻结期生效），列出要问用户的问题。

严重度按加载方式定：常驻 > 生成 > 按需；同一措辞在多处出现，或已能在代码里看到它催生的样例，再升一级。

完成：每个候选都有成立／例外／存疑之一的结论和依据。

## 4. 报告

按严重度排序，每条成立项包含：

1. `path:line` 与原文引用。
2. 所属模式、加载档位、严重度。
3. 危害机制（一两句）。
4. 改写建议：按该模式的改写方向，用正面陈述写出目标行为，保留原句里合理的约束。

另列例外项与存疑项，以及每条模式的命中统计。

用户授权修改时，按改写建议编辑，改完对改过的文件重跑第 2 步，确认命中只剩例外。

## 新增模式

用户描述一类新的有害提示时，按模式库开头的条目格式加一条。先确认它与已有条目的机制不同；机制相同、只是措辞不同，就把措辞补进已有条目的搜索线索。
