找出 **agent 容易照抄、并已在多处重复出现** 的错误或不良编程模式。代码库就是 agent 的记忆：改进要落在类型约束、lint、基础组件或重构上，让正确写法成为默认路径。默认只读：只出报告，被扫仓库不改、不提交，不为审计安装依赖或工具。

## 1. 范围、基线与历史

范围取用户本轮指定的仓库、路径或方向，缺省为当前工作区。记下仓库标识（`owner/name` 或本地名）和 HEAD **SHA**，证据的路径与行号都以该 SHA 为准。

先读历史，避免同仓同类再报。历史只来自本轮用户或调用方指定的文件或状态，未指定就当作没有历史。读法、去重与追加见 [历史](references/history.md)。指定的文件解析失败时，原样保留它、停止写入，并告诉用户。

## 2. 探索

按 [审计准则](references/criteria.md) 读代码、搜索引用并推理，找「新代码会照着写」的重复错误。用户指定了方向就沿该方向。每个仓库本轮最多报告**一个**新模式。工具命中只是线索，打开代码核对过才算证据。

## 3. 核实

- **真实且够数：** 至少 3 处独立、真实的出现，每处的路径、行号与描述在证据 SHA 上对得上。
- **是不良模式：** 本应不同的实现、有意的平台差异、只是长得像的代码不算。
- **会复发：** 容易被照抄，代码库没有约束住。
- **改进可执行：** 类型约束、lint / semgrep、基础组件封装或重构，落点明确；规则文档（如 `AGENTS.md`）的提醒不算改进。
- **未被覆盖：** 历史与既有 issue 里没有同仓同类。

没有可信的新模式就不凑。**完成标准**：报告里的模式过了这五关。

## 4. 报告

有可信新模式时交付中文报告：模式名称与规范化类别、证据（证据 SHA 与至少 3 处固定到 SHA 的路径行号链接）、影响（为何有害、为何易被照抄）、改进（可执行机制与落点）。交互式调用没有新模式时简短说明；自动或定时调用没有新模式时静默。结论限定为「在所述范围和方法内发现或未发现」。报告发出后，按 [历史](references/history.md) 追加本轮已报告的模式。
