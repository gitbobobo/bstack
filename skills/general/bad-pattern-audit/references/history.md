# 历史（可选）

历史用来避免同仓同类重复报告。

## 从哪里读

只使用本轮用户或调用方指定的历史文件，或调用方已经在维护的状态；没有指定就当作没有历史。

读到后先按仓库过滤，再按规范化类别（并对照模式名称与一句话摘要）判断是否同类。已被报告过的同类不再当作新发现。

指定的文件不存在，视为尚无历史，继续审计。文件存在但无法解析为预期结构：原样保留，向用户说明后继续只读工作，本轮不写入。

历史文件里可能已有 `reported` 数组，兼容这些常见字段：`repo`、`date`、`pattern`、`category`（可能缺失）、`summary` 或 `description`、`evidence`（路径或带 SHA 的链接）、`sha`（可能缺失），以及旧记录里的 `issue`。缺失的类别根据模式名称和摘要就近判断，明显同类的模式照样视为已报。

## 写什么

仅在调用方指明了写入位置（历史文件或调用方状态）时才写，报告发出后追加。没有新模式就不追加。

每条新记录追加到顶层 `reported` 数组：

| 字段 | 说明 |
| --- | --- |
| `repo` | 仓库标识 |
| `date`、`timezone` | `YYYY-MM-DD` 与时区 |
| `pattern` | 报告里用的模式名称 |
| `category` | 用于同仓去重的规范化类别 |
| `summary` | 一句话摘要 |
| `sha`、`evidence` | 本轮证据 SHA，以及各处路径/行号或带 SHA 的链接 |

调用方已有自己的状态格式时，按对方格式追加同等信息。

## 安全写入

- 先读后写，只追加本轮新记录，已有条目保持原样。
- 写到同目录临时文件再改名，避免写到一半留下损坏文件。
