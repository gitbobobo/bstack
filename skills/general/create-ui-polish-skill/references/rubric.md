# 评分标准

按正常、成熟的商业应用的标准打分。每张图 0–10 分，可以带一位小数。分数由五个维度相加，每个维度满分 2 分：

| 维度 | 看什么 |
|---|---|
| 空间比例 | 留白、密度、内容块大小和当前屏幕尺寸是否匹配，重心是否稳 |
| 视觉层级 | 主操作和主信息是否一眼可见，次要元素是否退后，分组是否清楚 |
| 风格一致性 | 控件形态、图标风格、圆角、材质在页内和跨主题是否统一 |
| 文字与控件可读性 | 对比度、字号、禁用态与可用态是否分得清，在最差的背景区域上也要看 |
| 精致度 | 对齐、边缘收口、渐变和模糊有没有瑕疵，有没有像没收好的布局 |

## 评审提示词

每一轮都开一个新的评审会话，把下面的内容填好后整段发给用户指定的评审员。方括号里的内容按本次截图填写。

```text
你是独立的 [平台与形态] 界面视觉评审。请用看图工具逐张打开下面的完整截图，不要只根据文件名推测：
[每行一个绝对路径，后面注明 主题 / 状态]

应用背景：[一两句话说明应用是什么，截图的设备尺寸和逻辑分辨率]
这些截图是什么：[每张图对应的界面、主题、状态；演示数据或不可用控件的真实原因]
产品约束（不能建议删除或改掉，但可以评价它们的比例、排版和对比）：
[从蓝图的「产品约束」里抄写与这些界面相关的条目]
布局蓝图（同一平台族的各平台应保持一致的布局）：
[粘贴蓝图的「共通」一节和本平台族的「布局」一节]
参照图（同族另一个已达标平台的同一界面，只用于判断布局是否一致，不打分）：
[每行一个绝对路径；没有就写「无」]

请逐张打分：空间比例、视觉层级、风格一致性、文字与控件可读性、精致度，每项 0–2 分，可以带一位小数，再给出总分。
每个扣分点都写明可见元素、位置、扣了多少分，并标出它是真实问题还是个人偏好。
另外单独列出截图和蓝图（以及参照图）布局不一致的地方，这一项不计入分数。
不要评价演示数据和封面美术，不要因为原生控件或留白本身扣分，截图无法证明的交互不要判成缺陷。
只看上面这些图片，不读源码、其他目录或其他评审结论，不修改文件，不启动子代理。看不了图就直接说明，不要编造。用中文回报，并确认打开了全部图片。
```

## 用法要点

- 评审员只看截图和这段提示词，看不到达标阈值，也看不到上一轮的分数。
- 一个评审会话只评一个平台：同一界面在这个平台上的所有 主题 × 状态 放在一起，图太多时按主题拆成几个会话。
- 记录到地图里的分数就是评审员给的总分，扣分点只记最主要的三到五条。
