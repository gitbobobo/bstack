## 哪些不能为填空位直接派出

- **INT-1621**：正文要求 iOS 满载冻结根因与连续三轮原生验收，不能仅因提到“核心队列”就派给 Mini 完成整项；需有真正独立且不依赖该前置的核心段才另判。
- **INT-1647**：已接受的持锁与 join 边界，正文明确需要核心恢复代数/可取消装回；先查前置当前是否已落地，不重复实施已否决的锁外恢复方案。
- **INT-1313、1311、1310**：分别涉及特定 HyperOS 现场、USB DAC、Cast；核真实设备、接收端与必要日志，模拟器不替代硬件验收。设备适配不消除验证缺口。
- **INT-1373**：Mini 可以写 Rust 适配器，但正文明确要求最新 fnOS 抓包及 FN Connect 直连/中继；先核服务端与授权可用性，旧逆向资料不足以直接启动整项实现。
- **INT-1599、799、1724、1714**：分别涉及降级 UI、配对范围与凭据传输、全选指示语义、超时文案语义；展开既有决策后区分技术选择与确实缺少的产品决定。只阻塞依赖未决语义的部分。
- **INT-1732、1789、1560、1791**：分别属于审查 nit、跨端词表扫描、机械注释清理、非门禁类型告警；可做不代表值得优先做。尤其动态本地化引用、空 Cargo feature 的外部消费者、已修复的旧行号都须核实，不能机械照扫描清单删除。
- 明确只有 Swift、桌面或 OHOS 的条目按仓库分工留给对应设备；`bstack:defer` 的 INT-801 保持排除。其他池满不构成 Mini 池停止筛选的理由。

## 提炼出的通用标准

1. **能力匹配**：以允许修改的模块与必需验证能力为单位，不以标题里的平台词或编程语言替代归属判断。
2. **闭环切片**：跨端可从共享层加本机消费者起步；保兼容、可独立验证合并、有剩余责任归属。未接入的空抽象不算成果。
3. **三态分诊**：可派、硬阻塞、待核分开。待核给最小查询；硬阻塞给具体依赖、产品决定或冲突证据。
4. **设计与准入分离**：派前查明为什么值得做及能交付什么；技术方案可由执行线程设计，产品授权与真实收益不能靠执行线程补造。
5. **余位驱动覆盖**：先遍历全量轻摘要，再按匹配能力分批展开；批次数不决定完成。仍有空位与派活预算时，匹配候选处置完才算筛选完成。
6. **组合校验**：按共享契约和模块核并行冲突，空位多不等于把相互依赖的重构并行派出。

通用规则落在 `t3-dispatch/SKILL.md` 的挑选与停止条件、`references/slicing.md` 的切片核验。上述问题编号与设备事实只留在本复盘，不写入通用技能。
